01 / Why

サービスを作った、その先の連絡に

バイブコーディングで作ったサービスにも、問い合わせを受けて返す場所が必要です。メール画面を一から作らず、自分のアドレスでやり取りを始められます。

専用の窓口を作る
サービスの連絡と個人のメールが混ざる。
独自ドメインのアドレスで受信し、そのアドレスから返信する。
見落としを減らす
受信トレイから毎回探し直す。
フォルダーを作り、差出人や件名のルールで整理する。
読む場所を増やす
別のアドレスへ何度も手で送り直す。
保存済みメールを手動転送する。継続して読みたい宛先には自動転送を設定する。
自分で管理する
保存先や処理を自分では変えられない。
自分のCloudflareアカウントに設置し、公開ソースを必要に応じて変更する。
02 / Quick start

用意するのは、自分のドメインとアカウント

BYOKは、利用者自身のアカウントと認証情報を使う方式です。Cloudflareはメール画面と保存先、Resendは送信を担当します。Noroshiの共通アカウントを借りる仕組みではありません。

  1. 独自ドメインを用意し、DNS（ドメインの接続先を指定する設定）をCloudflareで管理する。
  2. CloudflareとResendのアカウントを用意する。登録、規約同意、ログインは本人が行う。
  3. ソースを取得し、READMEのセットアップ手順に沿って自分の環境へ設置する。
  4. 最初の管理者を作成し、受信、送信、返信の到着をそれぞれ確認する。
ソースを手元へ取得
› git clone https://github.com/Chachamaru127/noroshi.git
› cd noroshi
# READMEの「セットアップ」を開き、前提と変更対象を確認

最初に決めるのは、使うドメインと管理するアカウントです。設置後はブラウザからログインして使います。ソースを取得しただけでは、メールはまだ開通しません。

AIと一緒に設定するには

Setup Skill（AIが読む導入手順書）を同梱しています。対応する環境へ導入すると、公式ドキュメントの確認と設定の案内に使えます。AIホストがブラウザ操作を提供し、本人が許可した場合に限り、公式画面への移動と状態確認を支援できます。利用できない場合は手動の手順へ切り替えます。

Skillはブラウザ機能を追加しません。ログイン、追加認証、支払い、秘密値の入力は人が行います。外部設定の自動変更は現行Skillの対象外です。設定を実行する対話型セットアップCLI（コマンド画面の補助プログラム）は別の経路です。

ソース公開とリリースの状態

GitHubのソースは公開されています。正式リリースは審査中で、Deploy to Cloudflareボタンはまだ無効です。公開ソースからの設置には、READMEに記載した前提環境と各サービスの設定が必要です。

03 / The loop

届いたメールが、返信になるまで

いつもの操作の裏で、受信、保存、送信を分担しています。外部サービスのアカウントと認証情報は、すべて利用者が管理します。

整理する
フォルダー / 振り分けルール
差出人や件名を条件にして、受信メールの移動先を決めます。
利用者：フォルダーと条件を設定する。
転送する
手動転送 / 自動転送
自動転送はメールを保存した後に実行します。宛先、有効と無効、状態を画面で確認できます。
利用者：転送先と共有する内容を確認する。
過去のメールを取り込む
EML取り込み
EML（メールを1通ずつ保存する形式）の取り込みを管理画面から行えます。元サービスからの書き出しは別途必要です。
利用者：取り込み先と元ファイルを確認する。

05 / Who

自分で作り、自分で使うメール環境に

向いている使い方
  • 個人開発や小さな活動の独自ドメインで連絡を受けたい。
  • 日本語のメール画面を、自分のクラウド環境へ設置したい。
  • 公開ソースを使い、必要な部分を自分で育てたい。
別の手段も検討したい場合
  • アカウント登録だけで使える、運用代行付きのメールサービスが必要。
  • 今のGmailアカウントを直接つなぎ、双方向で同期したい。
  • 組織向けの保管義務や稼働保証を、導入時点で満たす必要がある。

07 / FAQ

使い始める前によくある疑問

メールサーバーを自分で管理する必要はありますか？

専用サーバーを自分で用意する構成ではありません。Cloudflare Workersで画面と処理を動かし、受信にEmail Routing、送信にResendを使います。各サービスの契約と設定、稼働確認は必要です。

既存のGmailアカウントを接続できますか？

双方向のGmailコネクターは将来の機能です。現在は独自ドメインのメールを扱います。別アドレスへの転送と、既存アカウントの同期は別の機能です。

デモの送信ボタンを押すと、実際に送信されますか？

送信されません。ライブデモは架空のデータで操作を試すための画面です。実メールの送受信を使うには、自分の環境への設置と開通確認が必要です。

無料で使い続けられますか？

ソースはMITライセンスで公開しています。独自ドメインと外部サービスの費用は別です。利用量やプランで変わるため、導入時にCloudflareとResendの公式料金を確認してください。

AIに全部任せれば開通しますか？

現在の案内Skillは、設定の説明と確認を支援します。AIホストによって使える機能が異なります。アカウント取得、追加認証、秘密値入力、外部設定の変更には人の操作と判断が残ります。画面が開くだけで開通完了とはせず、送信と返信受信を個別に確かめます。

08 / Glossary

構成を読むための言葉

Cloudflare Workers = Noroshiの画面とメール処理を動かす実行環境。
Cloudflare Email Routing = ドメイン宛ての受信メールをWorkerへ届ける機能。
D1 / R2 = Cloudflareの保存サービス。D1は本文と索引、R2は添付ファイルを担当。
Resend = メールの送信と配信結果の通知を担当するサービス。
日々のメールは、この画面で
設置と開通確認を終えたら、ブラウザでログイン。受信を読み、返信し、フォルダーで整理する。普段のメール操作はNoroshiから行えます。
正直な但し書き
  • 公開ソースとライブデモを提供中です。正式リリースは審査中で、ワンクリックのDeployボタンはまだ無効です。
  • 3パターンの画面は非公式の比較デモです。Gmail、Outlook、Thunderbirdとの提携や互換接続を示すものではありません。
  • 設置したメール環境の運用と費用は利用者が管理します。すべてのAIクライアントで同じ導入体験を確認した段階ではありません。
